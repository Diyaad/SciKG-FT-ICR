2. IDENTITY FIELD PER NODE TYPE — THE MAP
================================================================================

The real identity field is a single top-level `identifier` (namespace:value),
present on 100% of records in every type. No node uses top-level id/doi/issn/
filename — those domain keys live INSIDE `properties`. The schema's per-type
id/doi/issn/filename identity story is stale; the data is uniform.

  entity_type | identity field | prefix(es) in data      | domain key in properties
  ------------|----------------|--------------------------|--------------------------
  Publication | identifier     | doi: (397), pub: (408)   | properties.doi (397 only)
  Researcher  | identifier     | researcher: (5031)       | — (ZERO orcid:)
  Journal     | identifier     | journal: (806)           | — (ZERO issn:)
  Funder      | identifier     | funder: (383)            | properties.ror_id
  Facility    | identifier     | facility: (819)          | —
  Instrument  | identifier     | instrument: (159)        | properties.psi_ms_id (no ms:)
  Dataset     | identifier     | dataset: (311)           | properties.accession
  RawDataFile | identifier     | rawfile: (998)           | properties.filename
  Sample      | identifier     | sample: (3)              | —
  Software    | identifier     | software: (8)            | — (no ms:)

For 04_validate: key every node on `identifier`; treat it as required + unique.
Do NOT require top-level id/doi/issn/filename (they don't exist). The schema's
"preferred external PID" strategies are unrealized: Researcher never uses orcid:,
Journal never issn:, Software/Instrument never ms: — all use minted internal
PIDs. Fine, but don't validate against the external-PID-preferred rule.

WARNING — entity_type != file. rawfiles_pxd.jsonl (984 lines) is 952 RawDataFile
+ 32 Dataset records. So Dataset lives in TWO files (datasets.jsonl 279 +
rawfiles_pxd.jsonl 32 = 311). The validator's identifier set and dangling-ref
check must scan ALL entity files, not assume one file per type.

--- SCHEMA §1  UNIVERSAL IDENTITY (verbatim, lines 99-124) --------------------
Every node carries a single top-level `identifier` (lowercase `namespace:value`)
— THE required, unique identity field for EVERY node type, 100% populated on disk
across all 10 populated types. On-disk key is `identifier`, NOT `id`: where a
per-node table shows an `id` row it means this top-level `identifier`.
Domain keys — doi, issn, accession, filename, ror_id — live INSIDE `properties`,
not as the identity field. External-PID-preferred rules are aspirational only:
Researcher never uses orcid:, Journal never issn:, Software/Instrument never ms:
— all use minted internal PIDs.
Uniqueness: `identifier` is unique for every type EXCEPT RawDataFile, whose
`rawfile:{filename}` value is not globally unique (64 PXD cross-deposits share
filenames); RawDataFile global uniqueness is enforced on `sha256_hash` instead.
One type spans multiple files: Dataset lives in TWO files — datasets.jsonl (CSV)
and embedded in rawfiles_pxd.jsonl (32 PXD datasets). Identity, uniqueness, and
dangling-ref checks must scan ALL entity files.

  source_type    | string   | api, csv, manual_annotation, fisher_py,

  confidence     | string   | high, medium, low

  evidence_note  | string   | free text

  schema_version | string   | v1.0
Every node AND every relationship carries all six. Missing any one -> quarantine.
