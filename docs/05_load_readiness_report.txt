R1 — db.py
================================================================================
a. WHAT'S IN IT
   A pure connection layer, nothing else. Four functions:
     - connect()         builds a GraphDatabase.driver from three env vars;
                         raises a clear error if any are missing
     - close(driver)
     - run_query(driver, cypher, params)  auto-commit session, parameterised
                         (never string-interpolates params)
     - test_connection() RETURN 1, then CALL dbms.components() for a version string
   __main__ runs test_connection().
   NO constraints, NO node types, NO identity logic, NO MERGE/load logic —
   its docstring says that all lives in 05_load.py.

   db.py cannot diverge from the schema on node types because it encodes none.
   It does not know Software, Dataset, Sample, Funder, Facility; it does not know
   software:{canonical_name} identity; it does not know Instrument/Dataset/Software
   each span two files — it contains zero schema knowledge and is source-agnostic
   plumbing.
   The real divergence is a CONTRACT GAP: SCIKG_SCHEMA.md line 53 says the Cypher
   constraints are "run at database setup via scripts/db.py," and db.py's docstring
   implies it — but db.py creates NO constraints.
   Write-date: not obtainable without git, but audit_repo.py (lines 447, 728-729)
   still calls db.py "absent / Not present," so db.py was written AFTER that audit,
   and audit_repo.py is now stale on this point.
